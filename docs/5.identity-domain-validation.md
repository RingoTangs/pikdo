## 6. User 与 Account 的跨模型一致性

### 6.1 稳定 UserId 与不同标识角色

Account 的 `userId` 就是 I1 UserId 类型，未创建另一种用户标识，也不把 AccountId、邮箱键转换为所有者。T5 验证从 User 取得的 UserId 可直接用于 Account；两个不同 AccountId 可以引用同一个 UserId，原实例属性保持不变。

同一 UUID 数值也不会使 UserId 和 AccountId 成为相同类型或相等的 Record 值。这由独立类型声明与 Record 的默认相等契约保证，未为 Java 类型机制新增反射或重复单测。该判断不证明未来业务资源已经接入所有权检查。

### 6.2 状态与关联解耦

User 只持有 id/status，Account 只持有 id/userId/email；双方没有可导航的对方对象或 Account 集合。User 禁用和恢复不可能通过当前代码路径修改 Account 字段。

T5 的状态测试在禁用并恢复后验证引用不变，未在 DISABLED 中间点单独断言所有 Account 字段；该中间状态的隔离同时由 final 字段、没有双向对象引用及 User 两个赋值方法的源码审查确认。不能把这一证据说成已执行中间状态的独立集成测试，也没有为此添加等价测试。

Account 不知道 User 当前是否 ACTIVE，不提供 canLogin 等替代未来授权流程的方法。User 的状态幂等仅为重复赋值后状态不变，不证明请求去重、数据库幂等或 exactly-once。

### 6.3 邮箱值相等与 Account 实例身份

不同 EmailAddress 对象可以按相同 canonicalAddress 相等，但 Account 不重写 equals/hashCode。两个独立构造的 Account 不会仅因持有相同邮箱而自动相等；AccountId 也不会自动赋予两个 Java 实例值相等语义。

该结论由 Account 继承 Object 行为的源码及 javap 证据确认，现有 T5 不专门断言“相同邮箱的两个 Account 不等”。不为验证未重写 equals 的 Java 默认行为增加形式测试。实体身份、邮箱身份和长期用户身份分别由 AccountId、EmailAddress、UserId 表达，不能互换。

## 7. EmailAddress 格式、相等性与安全审查

### 7.1 格式与长度

私有构造器先拒绝 null；`validate` 再拒绝空字符串、超长地址及非 ASCII 可打印输入，确认唯一 @ 与非空两侧。本地部分按允许字符和单点分段检查；域名保留空标签进行检查，避免尾点被拆分操作丢弃，且逐标签检查长度和字符。

六个长度测试的构造相互独立：本地部分 64/65，标签 63/64，完整地址 254/255。完整边界使用 64 字符本地部分及 63、63、61/62 字符域名标签，其他格式约束均成立，因此不是因其他无效条件而误通过拒绝测试。

IP 规则与 I2 补充确认一致：拒绝方括号 IPv4/IPv6，以及四段纯十进制且各为 0～255 的裸 IPv4，包括前导零。不做网络解析，也不支持其他历史数字主机表示的自动解释。`alice@256.1.1.1` 在当前有限标签语法下合法，是 T4 明确保留的范围，不按有效 IPv4 拒绝；这不是域名可投递性承诺。

裸 IPv4 的累计值每次超过 255 即返回非 IPv4，继续计算前的值最多为 255，因而没有长数字段造成整数溢出的路径。标签长度仍受 63 限制。未发现需要修复的校验边界。

### 7.2 规范化与集合行为

逐字符只改变 ASCII A～Z，其他受支持字符保留；不调用默认 Locale 转换、不去点或标签、不合并域名、不做 IDNA、Unicode 或服务商别名处理。T4 在美国英语与土耳其语默认 Locale 下比较结果，finally 恢复默认及 DISPLAY、FORMAT 设置，并使用 Locale ResourceLock。

equals 对 null、其他类型及不同键正确返回不等；同键对象满足自反、对称、传递和一致性，hashCode 同样仅依赖键。HashSet 保留首次加入实例，HashMap 可通过等价对象查值。两个对象仍各自保留原始拼写，集合操作未改变已保存表示。

### 7.3 安全意义的限制

`Alice@example.com` 与 `alice@example.com` 是同一 Pikdo 身份键，但不证明实际邮件系统投递给同一个人。EmailAddress 的类注释明确拒绝把构造或 equals 当作邮箱控制权证明、可信收件地址替换许可。

当前没有邮件发送、账号恢复或授权入口，所以不能通过本轮测试声称这些流程已安全执行。未来邮件认证、重置及敏感通知必须选择可信已验证的原始地址，不能用未经验证的相等对象替换目标；查到相同邮箱也不能直接授予既有 UserId 的访问权限。

没有增加自定义邮箱 toString、日志输出或序列化接口，不新增完整邮箱的调试输出路径。安全审查结论限于当前模型边界，不是对未来使用者的实现担保。

## 10. 领域依赖与结构边界
