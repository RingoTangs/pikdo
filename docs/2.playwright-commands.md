# Playwright 生产采集与 browser-probe（v0.4.0a1）

Phase 2C 已收敛为 Playwright-only 的统一采集入口：只保留 GET /health 和 POST collect。旧 resolve API、批量 CLI、文件归档及 HTTPX 上游业务均已移除。
`/health` 仍为本地存活检查；POST collect 成功只返回现有 Product，不保存或返回原始 JSON。

## 安装与浏览器选择

```bash
cd collector
uv sync
uv run playwright install chromium
```

Playwright Python 包和浏览器二进制分别安装；升级依赖后应重新安装对应版本的浏览器。

```bash
uv run playwright install --list
uv run playwright install --dry-run chromium
```

默认使用 Playwright 自带 Chromium、headless 模式。系统已安装 Google Chrome 时可使用 `--channel chrome`；这不会读取日常 Chrome Profile。
`--headed` 显示独立的临时浏览器窗口。没有桌面会话或缺少浏览器二进制时可能启动失败。

## 生产 API 与生命周期

唯一商品采集接口是 POST `/api/v1/xhs/products/collect`，成功返回标准化 Product。
商品 GET 接口已移除，没有兼容路由。Collector 不提供数据库查询；未来查询、缓存及任务管理由 Java SaaS 服务负责。

```bash
uv run dev
curl -X POST http://127.0.0.1:8000/api/v1/xhs/products/collect \
  -H 'Content-Type: application/json' \
  -d '{"input":"https://xhslink.com/m/4tQFfvENODH"}'
curl -X POST http://127.0.0.1:8000/api/v1/xhs/products/collect \
  -H 'Content-Type: application/json' \
  -d '{"input":"6ac8da9a7e1073000114c7ae"}'
```

Lifespan 启动一个 Chromium Browser，多次请求复用它；每次请求使用新的非持久化 BrowserContext。
Browser 是进程，Context 是隔离 Cookie/LocalStorage 的存储环境；Context 在成功、失败、超时和取消后关闭，完成清理才释放并发许可。
启动失败 fail-fast；运行期断开后不自动重启。关闭服务先停止请求和任务，再释放 Browser、Playwright。

`create_app(browser_config=BrowserConfig(...))` 支持 headless=True、channel=None 或 chrome、并发=1、排队=5 秒、导航=30 秒、响应=15 秒、清理=5 秒。
清理期限分别适用于监听任务等待、CDP detach、Context close、Browser close 和 Playwright stop；各阶段分别有界，启动及 Context 创建受导航期限约束。
等待许可不会创建 Context，Semaphore 只限制同时采集数，没有额外队列容量配置。排队超时为 BROWSER_BUSY。
POST 支持商品 ID、官方 H5 URL、xhslink 短链和完整分享文案。纯 ID 没有分享上下文；分享输入直接从原始短链导航。所有输入均通过同一采集流程，不通过 HTTPX 请求商品详情，也没有自动兜底。

明确访问限制后，同管理器的运行中、等待和新采集都停止，返回 BROWSER_ACCESS_RESTRICTED。
浏览器失效或清理失败会停用管理器；清理失败不覆盖已发生的采集错误，没有主错误时返回 BROWSER_UNAVAILABLE。没有自动恢复操作；停止访问并人工检查。
不存在另一条 HTTPX 上游路径或兜底。Input Parser 只做本地验证；纯本地健康检查不受限制状态影响。

POST collect 错误统一只有 code/message。输入验证错误不会回显分享文案。
HTTP 映射：422 输入错误；404 仅明确下架；502 导航/响应/身份错误；503 不可用、受限或忙；504 导航/响应超时。
生产安装必须同时具备 Python Playwright 包和对应 Chromium 二进制。

## Phase 2D：主错误与清理诊断

采集失败后，即使清理也失败，仍保留原始采集错误。例如商品响应 HTTP 461 加 CDP detach 超时，
主要结果为 `BROWSER_ACCESS_RESTRICTED`，独立记录 `cleanup_error=BROWSER_UNAVAILABLE`、`stage=cdp_detach`、`outcome=timeout`。
若采集成功但关键清理失败，则返回 `BROWSER_UNAVAILABLE`，不报告 SUCCESS、不写 Probe 原始输出。
调用方取消在必要清理后继续传播 CancelledError，不转换为普通采集失败。

Manager 将访问限制状态与资源健康分开记录：受限后保持 restricted，清理失败同时标记资源不健康并关闭共享 Browser。
当前、排队及后续请求不会因此恢复采集；普通清理故障进入 unavailable。主动关闭 Browser 的断开事件不会再次取消正在保留主错误的请求。
Context、CDP 和任务清理各自有界；任务未结束时保留引用，Context 关闭后再次回收，必要时关闭 Browser。
Browser 关闭失败会进一步停止 Playwright；若资源关闭本身仍失败，保留失败诊断和已知资源引用，禁止复用，等待人工检查。
不自动重启、不重试上游请求，不通过增大默认清理期限掩盖问题。

标准 logging 名称为 `xhs.browser`，事件使用固定 key=value 字段。默认 WARNING 可见限制与清理失败；
启用 INFO 可查看 started/completed 和状态变化。关联字段为随机 `collection_id`，与商品分享信息无关。
字段包括 `error_code`、`cleanup_error`、`stage`、`outcome`、`elapsed_ms`、主页面/商品 HTTP 状态及 Manager 状态。
阶段标识为 `listeners_remove`、`watchers_cancel`、`watchers_join`、`cdp_detach`、`context_close`、`browser_close`、`playwright_stop`，仅记录实际执行阶段。
不记录输入、URL、请求头、正文或原始异常堆栈。API 错误仍仅有 code/message，不公开内部清理记录。

需要完整本地诊断日志时，可使用原有 Probe 参数：

```bash
uv run python -c 'import logging, sys; from xhs.browser_probe import main; logging.basicConfig(level=logging.INFO, format="%(message)s"); sys.exit(main())' \
  --input "https://xhslink.com/m/4tQFfvENODH"
```

离线测试已复现 HTTP 461 被 detach 超时、Context close 错误覆盖，以及取消被清理错误覆盖的旧行为。
这不证明用户观察到的 7.125 秒耗时来自某个特定清理阶段，也不证明 headless 或浏览器 channel 是访问限制的原因。
Phase 2D 不访问真实小红书、不改变启动参数或采集策略；本地 Chromium 验证仅访问 loopback。

## 独立单商品探测

```bash
uv run browser-probe --help
uv run browser-probe --input "https://xhslink.com/m/4tQFfvENODH"
uv run browser-probe \
  --input "https://xhslink.com/m/4tQFfvENODH" \
  --headed --channel chrome --output .browser-probe
```

`--input` 支持完整分享文案、原始 xhslink 短链、官方 H5 商品 URL 和 24 位商品 ID。
短链直接由浏览器导航，原始查询参数和可信重定向上下文保留在内存中，不经过 HTTPX 解析或去参重建。
纯 ID 从规范 H5 URL 导航，CLI 会提示没有原始分享上下文；这可能与真实分享入口得到不同结果。

默认导航（包括等待进入商品页）最多 30 秒；进入商品页后等待匹配响应及完整正文最多 15 秒。
`--timeout SECONDS` 将这两个阶段各自的上限设置为指定的有限正数，不表示整个命令的总期限。
浏览器启动也使用导航超时。无固定 sleep 成功判断、并发采集或自动重试。

## 结果和原始字节

CLI 输出启动状态、导航状态、商品 ID、商品及店铺名称、商品响应 HTTP 状态、JSON 字节数、SHA-256、总耗时与结果码。
名称含可疑凭据信息或 URL 时隐藏；失败不打印浏览器异常正文、请求头、Cookie、签名或分享 URL。

成功结果为 `SUCCESS`、退出 0；采集或输出失败退出 1；命令参数错误退出 2。

| 错误码                             | 含义                                                     |
| ---------------------------------- | -------------------------------------------------------- |
| `BROWSER_BUSY`                     | 等待并发采集许可超时（生产管理器）                       |
| `BROWSER_UNAVAILABLE`              | Browser 断开、管理器停用或清理失败                       |
| `BROWSER_LAUNCH_FAILED`            | 浏览器、Context 或 Page 初始化失败；检查二进制和运行权限 |
| `BROWSER_NAVIGATION_TIMEOUT`       | 导航或等待进入商品页面超时                               |
| `BROWSER_NAVIGATION_FAILED`        | 页面导航或浏览器控制失败                                 |
| `BROWSER_UNTRUSTED_REDIRECT`       | 不支持的主页面地址已被阻止                               |
| `BROWSER_PRODUCT_RESPONSE_TIMEOUT` | 未在期限内获得当前商品的完整详情响应                     |
| `BROWSER_PRODUCT_RESPONSE_MISSING` | 页面提前关闭、崩溃或正文无法完整读取                     |
| `BROWSER_ACCESS_RESTRICTED`        | HTTP 401/403/429/461、登录、安全验证或明确业务限制       |
| `BROWSER_PRODUCT_UNAVAILABLE`      | 上游明确表示商品不存在、已下架或已失效                   |
| `BROWSER_INVALID_RESPONSE`         | HTTP 异常、无效 JSON、业务失败或缺少可信商品身份         |
| `BROWSER_PRODUCT_ID_MISMATCH`      | 页面、输入或响应商品身份不一致                           |
| `BROWSER_UNSAFE_OUTPUT`            | 输出位置不安全、未被 Git 忽略或属于正式归档              |
| `BROWSER_OUTPUT_IO_ERROR`          | 调试输出文件操作失败                                     |
| `BROWSER_INTERRUPTED`              | 用户中断                                                 |

本地输入校验失败使用 InputError，保留既有错误码，例如 `INVALID_PRODUCT_INPUT` 和 `AMBIGUOUS_PRODUCT_INPUT`。
响应超时只说明未获得有效匹配响应，不能据此判断商品已下架，也不能证明一定是风控。

不指定 `--output` 时不写文件。指定后只有采集验证成功才写 `response.json`，不进入任何归档系统。
正文直接来自同一次 Playwright `response.body()`；这是浏览器提供的解压后正文，不是压缩传输帧或响应头。
不经 JSON/Pydantic 重编码、脱敏、排序或格式化。使用同目录临时文件、flush/fsync、`os.replace` 原子替换，失败不会以新响应覆盖旧文件。

建议使用已被 Git 忽略的 `collector/.browser-probe/`。仓库内自定义输出必须先加入忽略规则；仓库外目录不受此要求限制。
禁止写入原始 examples、带历史归档标记的目录及符号链接路径。目录标记 `.pikdo-browser-probe` 让项目格式化工具跳过调试正文；不要删除标记后格式化这些原始数据。
原始正文仍可能含敏感信息，仅用于本地调试，不应复制到日志、Issue 或 PR。

## 捕获与边界

导航之前注册页面响应监听。严格匹配 GET、`mall.xiaohongshu.com`、完整详情接口路径和唯一合法的 `item_id`。
响应早于页面身份确定时，只在内存暂存候选响应；商品身份确定后忽略其他商品响应。
校验 HTTP、JSON、`success=true`、详情结构和明确的商品 `itemId`，SKU ID 可以不同但不能代替商品 ID。
浏览器结果包含商品 ID、Product、原始 bytes、HTTP 状态和 `collection_method="playwright"`；不改变生产响应类型。

Playwright 的 `page.route()` 对服务端重定向只处理第一个 URL，因此主框架 Document 导航使用 Chromium CDP Fetch 请求阶段逐跳校验，放行时不修改 URL、头或正文。
该控制只用于导航安全，不主动构造详情请求；详情仍由页面正常加载发出，并从 Playwright 响应事件读取。

每次使用独立非持久化 Context；成功、异常和取消均释放资源。不使用 storage_state、用户 Profile、外部 Cookie、代理轮换、stealth 或验证绕过。
遇到登录、验证码和访问限制立即停止，不刷新或重试。

## Phase 2B 清理与数据保护

纯输入解析位于 input_parser.py，CollectRequest 只接受 1–8192 字符字符串 input，拒绝额外字段，不回显敏感输入。
Product Decoder 保持严格 JSON、Decimal 和身份校验，不再保留旧客户端的绕过校验模式；Product 业务字段不变。
HTTPX 仅为 TestClient 开发依赖，生产依赖不再包含它；没有可调用的旧客户端、网络 Resolver、批量 CLI 或归档系统。

format/lint 不再处理原始 examples 的任何文件。历史 `.pikdo-example-archive` 和 probe 标记目录及后代也完全跳过，直接 JSON 格式化同样受保护。
默认历史忽略规则保留，旧商品数据、manifest、锁文件与标记不会被自动删除、迁移或恢复。
生产 API 不持久化原始响应；可选 browser-probe 输出仍采用符号链接拒绝、Git 忽略检查和原子替换。
